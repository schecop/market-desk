# Learning Journal

The trace of **what was built, why, and what was learned**, one file per sprint. Written during the work, not after. Re-read it whenever you come back after a break, or before explaining the project to someone.

| File | Sprint |
|---|---|
| [`sprint-0.md`](sprint-0.md) | Scaffold |

New sprint: copy [`_template.md`](_template.md) to `sprint-N.md` and add it to the table.

## What goes where
| Record | Where | When |
|---|---|---|
| Where we are, next step | `PROGRESS.md` | end of every session |
| Small decisions (with alternatives) | journal → Decisions log | when made |
| Lasting architectural decisions | `docs/adr/NNNN-*.md` + a line in the journal | when made |
| Concepts learned | journal → Concepts | when first met |
| Which file does what, and why | journal → Code map | when the file is created or changes role |
| Bugs, surprises | journal → Gotchas | when solved |
| Why a change was made | commit body + PR description | every commit / PR |
